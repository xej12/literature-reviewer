# 文献梳理工具：可用性审查记录

审查日期：2026-10-17  
审查方式：本地服务真实浏览流程 + Chrome 自动化检查  
测试数据：本机 Zotero 10.0.6，14 篇文献  
测试窗口：1440×900 桌面窗口、390×844 窄屏窗口

这份记录用于决定下一轮改动，当前只记录问题，不代表已经同意全部修改。

## 优先处理

### 1. 窄屏无法进入文献详情（阻断）

在窗口宽度小于 1050px 时，右侧详情栏被 CSS 直接隐藏。此时可以看到文献列表，但点击文献后没有详情、PDF、论文解读、术语和图表解析入口。自动化检查在 390px 和 1024px 窗口都无法找到可见的详情操作。

建议：窄屏改成点击条目后打开详情抽屉或独立详情页；详情页内继续提供 PDF、解读和缓存结果入口。不要仅仅把右栏缩窄，因为按钮和摘要会失去可读性。

### 2. 图表解析仍然以整页为输入，图表细节可能不够清楚

当前发送给视觉模型的是整张 PDF 页面。双栏论文中，图表通常只占页面的一小部分，坐标轴、图例和小字号标注会被缩小。预览中的放大和高清原图只能帮助人查看，不能让模型自动聚焦到具体图表。一个页面包含多幅图时，结果也会混在一起。

建议：下一步增加图表区域选择或自动检测。至少允许用户在左侧框选一个区域，再把裁剪后的图片发给模型；解析结果应对应一个明确的图或表编号。

### 3. 文献列表没有分页或“加载更多”

前端固定请求最多 100 篇，超过 100 篇的 Zotero 条目不会显示，也没有提示。文献库增长后会出现“库里明明有文献但搜索不到”的误解。

建议：加入分页或加载更多，并显示当前结果范围；搜索时也应明确是在当前集合还是全部文献中检索。

### 4. 结果只能在网页中查看，缺少可复用的导出

论文解读、术语和图表结果虽然保存成 JSON，但用户无法从界面导出 Markdown、HTML 或带来源页码的笔记。科研工作中通常需要把结果放进笔记、报告或项目文档。

建议：先提供“复制为 Markdown”和“下载 Markdown”两个动作，并在导出内容中保留文献标题、模型、生成时间和页码。

## 影响可信度和安全性的不足

### 5. API Key 以明文保存在本机 JSON

`data/settings.json` 中保存完整 API Key。它没有进入 Git，但同一台电脑上的其他进程或备份工具仍可能读取。

建议：Windows 使用凭据管理器保存 Key；界面只显示掩码。至少在 README 中明确这是个人工具的本地安全边界。

### 6. 模型能力没有在配置时校验

论文总结和术语提取使用文本输入，图表解析需要视觉输入。当前设置界面只检查地址、模型名和 Key，不会提前告诉用户当前模型是否支持图片。失败时可能只能看到原始 HTTP 错误。

建议：增加“测试连接”和“测试图片能力”，并把模型能力显示为文本模型 / 视觉模型；图表解析失败时给出可操作的提示。

### 7. 缓存缺少版本和来源变化提示

缓存按条目键、附件键和页码保存，但没有记录 PDF 内容哈希。若 Zotero 替换同一附件文件，旧图表结果仍可能被当成最新结果。模型配置变化后，结果文件的全局模型字段也可能无法准确表示每个分析项使用的模型。

建议：缓存记录附件哈希、单项生成时间和单项模型；文件变化后提示重新解析。

### 8. 扫描型 PDF 的降级路径不清楚

文本提取依赖 PDF 文本层。扫描 PDF 没有文本层时，论文总结和术语提取可能只依据元数据或很少内容，界面没有明显提示“本文无法提取正文”。

建议：检测正文提取量，明确提示需要 OCR，并提供逐页 OCR 或手动上传文本的后续路径。

## 交互和效率问题

### 9. 图表解析存在重复的重新解析按钮

解析结果出现后，右侧顶部的主按钮和结果底部都会显示“重新解析（消耗 Token）”。两个按钮执行同一动作，会增加视觉噪声，也容易让用户误以为有两个不同的重新解析范围。

建议：保留一个按钮，固定在结果顶部或底部即可。

### 10. 模态框键盘操作不完整

弹窗可以点击关闭按钮或遮罩关闭，但没有 Escape 关闭，也没有焦点锁定。键盘用户打开弹窗后，Tab 可能移动到背景页面。

建议：补充 Escape、焦点锁定和关闭后焦点回到触发按钮。

### 11. PDF、摘要和分析之间没有来源联动

模型结果虽然要求页码，但用户需要自己在原始 PDF 中寻找对应位置。打开 PDF 会进入新标签页，返回工具后上下文已经分离。

建议：让结果中的页码可以直接打开对应 PDF 页面；后续再考虑高亮文本或图表区域。

### 12. 搜索和筛选范围偏窄

当前搜索主要覆盖标题和摘要；作者、DOI、标签、全文和集合没有统一搜索入口，也没有按年份、是否有 PDF、是否已完成分析筛选。

建议：先增加作者、标签和 DOI 搜索，再加分析状态筛选，避免一次引入过复杂的高级检索界面。

### 13. 长时间模型请求缺少可见状态和取消动作

模型请求可能持续较长时间，界面只显示“正在解析”或“正在解读”，没有阶段信息、已等待时间或取消按钮。网络问题时用户容易重复点击。

建议：显示“准备页面 / 上传图片 / 等待模型 / 保存结果”等阶段，禁用重复操作，并提供取消请求。

## 当前做得比较好的地方

- Zotero 数据以只读方式读取，个人数据库没有写入风险；
- 原始 PDF 直接打开，符合用户对“阅读正文”的直觉；
- 解读和术语结果按文献缓存，重复打开不会自动消耗 Token；
- 图表解析已经具备页码、左右翻页、缩放和原图查看；
- 视觉模型结果明确区分图表内容、趋势、核心结论和注意事项；
- API 配置在网页中完成，仓库不会包含个人 Key、缓存和 PDF。
