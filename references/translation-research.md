# 专业翻译与划词方案调研（2026-10-18）

本次核对 GitHub 项目的 README、功能与适用环境。翻译软件的功能成熟度不代表每个专业词汇都准确；术语表必须可追溯、可纠正，模型不确定时保留英文。

| 项目 | 核实到的能力 | 本项目采用方式 |
| --- | --- | --- |
| [Translate for Zotero](https://github.com/windingwind/zotero-pdf-translate) | Zotero 内 PDF 划词弹窗、手动翻译、词典、20+ 服务；DeepL glossaryId、有道 VOCABID 等术语表接入 | 参考“手动触发 + 词典/术语优先 + 原译文对照”交互；它是 Zotero 插件，不能直接作为本网页的组件。未复制插件源码。 |
| [NextAI Translator](https://github.com/nextai-translator/nextai-translator)（原 OpenAI Translator） | 选中文字翻译、多平台、词汇本、可修改原文、LLM 服务 | 参考选中内容的专门翻译面板；不引入整套桌面程序，复用用户现有模型配置。未复制源码。 |

通过 GitHub 代码搜索 `coronagraph 日冕仪`，可见日冕仪的对应译法，但词典仓库同一词条下还包含明显错误的短语翻译，不能批量当作权威数据导入。初始术语只记录用户明确确认的 `coronagraph → 日冕仪`（含复数），标明来源“用户确认的专业译法”。不声称具有已审核的完整天文词典。用户可逐项增加专业术语、领域说明，并纠正已有词条。

## 当前实现

- PDF 阅读器采用 PDF.js 的原始版式与文字层，默认适应宽度，左右翻页，支持页码与缩放；原始 PDF 独立入口保留。扫描页缺少文字层时提示，不伪造 OCR。
- 文献标题、摘要、原文依据、解读文字和新阅读器里的文字均可划词。划词只显示按钮，点击才查询。截图式图表预览里的像素不属于可选文字，需打开划词阅读器。
- 精确命中个人术语表直接本地返回，不调用模型；句子翻译结合标题、摘要、前后文、匹配术语。PDF 的上下文由后端从所属附件的当前页提取，校验附件归属。
- 译文、解释、不确定性分开显示；术语表未在译文中落实时明确提示核对。模型输出不能证明译法是权威标准。
- 模型译文按文献保存至忽略的 `data/translations/<itemKey>/`。缓存依据原文（保留大小写）、上下文、文献信息、术语表版本及服务/模型匹配；相同输入直接复用。并发请求串行查缓存，避免重复计费。重新翻译需要确认；失败不会覆盖已有成功缓存。
- 个人术语表保存在忽略的 `data/terminology.json`，共享给后续生成的深读、术语解释、图表讲解及旧式摘要。已有内容不会自动调用模型更新。
- DeepSeek 官方交互翻译关闭思考、沿用非思考默认预算；其他兼容服务不发送专有参数。深读设置中的输出预算只影响深读，不应用于划词翻译。
- API Key 仅留后端；没有新增第三方翻译代理，也没有安装 Zotero 插件。软件测试使用模拟模型响应，不调用付费 API。

PDF.js 依赖来源：`https://registry.npmjs.org/pdfjs-dist/-/pdfjs-dist-5.4.149.tgz`。本地仅保留浏览器需要的 build、文字层 CSS、字符映射、字体、WASM/ICC 资源和许可证。日常阅读无需连接 CDN。
