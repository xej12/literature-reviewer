# 常见问题与故障排查

[返回首页](../README.md) · [安装指南](installation.md) · [使用指南](usage.md)

先在项目根目录运行环境检查，它不会调用模型：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Check
```

## 不能安装或启动

| 现象 | 优先检查 |
| --- | --- |
| `python` 不是命令，或打开 Microsoft Store | 重新安装 Python 并勾选 PATH，关闭旧终端后重开；已有 Python Launcher 时用 `py -3 --version` 确认 |
| `No module named pypdf/pdf2image/PIL` | 用 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`；不要给另一个 Python 装依赖 |
| pip 下载超时、证书或代理报错 | 检查网络、系统时间及组织代理；使用自己信任的软件源，不要通过关闭证书校验来掩盖错误 |
| 无法执行 PowerShell 脚本 | 按安装指南使用带 `-NoProfile -ExecutionPolicy Bypass -File` 的命令；它只影响该进程。组织策略仍可能限制运行 |
| `WinError 10048` / 地址已占用 | 可能已有服务在运行，先尝试打开网页；或使用下面的备用端口 |
| `ModuleNotFoundError: winreg` | 当前版本只支持 Windows；不要把 macOS/Linux 安装当成已支持的流程 |
| 双击 `start.cmd` 后提示找不到 Python | 安装 Python 3.11+ 并按安装指南创建 `.venv`；当前项目不提供独立可执行安装包 |

换一个端口，不影响原来的服务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Port 8766
```

然后打开 <http://127.0.0.1:8766>。也支持环境变量 `LITERATURE_REVIEWER_PORT`；显式 `-Port` 优先。

## 网页和 Zotero

**网页打不开 / 连接被拒绝：** 确认启动窗口还在运行，并使用窗口打印的地址。GitHub 页面不是运行中的文献工具。关闭窗口、关机后本地网页也会停止；再次启动即可。不要为了启动本地网页开放路由器端口。

**“未找到 Zotero 数据目录”：** 在 Zotero 设置里找到直接含 `zotero.sqlite` 的目录，然后按 [指定目录步骤](installation.md#5-找不到-zotero-时指定数据目录) 设置 `ZOTERO_DATA_DIR`，重启服务。这里用的是本电脑数据库，Zotero Web 登录或 Zotero API Key 不能替代它。

**集合或文献没更新：** 在 Zotero 中完成修改后，点击网页“刷新文献库”；仍不更新时重启本地服务并核对数据目录。不要移动或删除正在使用的 `zotero.sqlite`。

**文献没有 PDF 按钮 / 附件找不到：** 先在 Zotero 本身双击附件。远程附件需先下载；链接文件若被移动，需要在 Zotero 修正链接。网页不能从仅有题录的记录自动找回全文。

**数据库锁定或读取异常：** Zotero 默认会独占数据库。本版查询经过变更检测和完整性校验的临时副本，包含已提交的 WAL 数据，不直接用 SQLite 打开原库，不用 `immutable` 绕过锁。查询结束或异常时关闭连接并清理副本；复制期间检测到数据库持续变化、维护或副本异常时，会提示稍后刷新，不返回未经校验的数据。临时复制和校验会增加读取开销，大库刷新可能稍慢。不要复制来源不明的 SQLite 文件覆盖自己的库。

**Zotero 卡在加载进度条：** 先停止文献工具服务，再正常打开 Zotero 做隔离检查。早期版本只读连接没有明确关闭，仍可能占用 WAL 文件，影响 Zotero 申请独占访问；请更新到包含连接释放修复的版本。如果停止工具后依然卡住，不能据此归因于网站，可进一步查看 Zotero 的启动日志或排查插件。不要删除数据库、WAL/SHM 文件或强制替换文献库。

## PDF 与图表

**“Unable to get page count” / “Is poppler installed and in PATH?”：** Python 包 `pdf2image` 之外，还需安装 Poppler。新开终端分别运行 `pdfinfo -v` 和 `pdftoppm -v`；若命令找不到，检查 PATH 是否指向含这两个 EXE 的目录，并从该终端重启服务。

**原始 PDF 能打开，文字解读却提示无正文：** PDF 可能是扫描件、文字以轮廓绘制或提取失败。当前不提供 OCR；有文字层的 PDF 更适合全文深读。

**图看不清或解释太笼统：** 先放大原页，再只框选一张图/表，使用支持图片输入的模型。模型可能无法辨认微小符号；精讲并不等于可靠 OCR，关键数值请核对原文。

**划词没有反应：** 使用“划词阅读 PDF”，不是截图式图表预览或浏览器独立 PDF 标签；扫描页没有文字层。选中后还需点击翻译按钮。

## 模型连接与生成

| 错误或现象 | 排查方式 |
| --- | --- |
| HTTP 401 / 403 | 核对 Key、API 权限及服务商限制；不要把密钥贴进 Issue |
| HTTP 404 / model not found | 核对基础地址和精确模型 ID，勿在基础地址后重复填写 `/chat/completions` |
| HTTP 429 / quota / insufficient balance | 检查服务商额度、余额与限速；不保证聊天产品订阅包含 API 余额 |
| HTTP 400 / image input not supported | 当前模型可能不支持图像，图表功能需要支持图片输入的 Chat Completions 模型 |
| `WinError 10013` / 套接字访问被拒绝 | 检查本电脑防火墙、组织网络、VPN/代理和服务商地址；确认 Python 被允许访问该地址。不要整体关闭防火墙；组织策略需联系管理员 |
| 保存配置后仍使用旧地址或模型 | 检查启动终端是否设置了 `OPENAI_*` 或 `LITERATURE_REVIEWER_*` 覆盖变量，然后重启服务 |
| 测试连接提示服务可达但未确认模型 | 该服务没有提供标准 `/models` 接口；核对模型 ID 后保存配置，再按需生成一次 |
| 文字调用正常，图表/深读失败 | 基本文字接口可用不代表支持图片、长文或结构化输出；核对服务商能力和返回错误 |
| 长时间等待 | 模型响应可能较慢；深读最长等待约 600 秒。不再需要时关闭解析窗口，避免反复点击重新生成 |

连接测试本身也会发送模型请求，可能收费。没有配置 API 时，仍可先浏览题录和原始 PDF。

**“答复不是有效 JSON / 待整理”：** 先看已保存正文，尝试“重新整理已存答复（免费）”。它不会补写模型未生成的内容；确需重新生成时再确认付费请求。已有成功结果与历史会保留。

**“达到长度限制 / 未生成正文”：** 查看模型设置的输出预算及服务商的上下文/输出限制。思考 Token 可能占用预算；较小预算不保证正文足够。适当调整预算，或在支持的服务上降低思考强度，再决定是否重生成；免费整理不能恢复被服务截掉的正文。

**“没有可核实引文 / 待评估”：** 已返回的优先级理由不能在输入材料中核实，程序不会采用分数。可查看已存答复或手动调整等级；不要把待评估理解为系统认为论文质量差。

## 分区、缓存和隐私

**看不到 IF / 分区：** 先按安装指南导入期刊表。匹配可能失败或期刊不在数据中，只有 IF 也不一定有分区；“暂无分区信息”不等于期刊不好。当前固定为数据清单指定年度，不会自动变为当年最新版。

**反复要求生成：** 确认打开的是同一文献、同一章节/术语/图表区域；文献材料、术语表或相关设置版本变化可能影响缓存匹配。查看历史版本，确认没有换到新解压目录后遗失原 `data/`。

**关闭后为什么还有费用：** 取消会中断本电脑请求并断开上游连接，已消耗的 Token 不能撤回，服务商是否立即停止生成和最终计费由其决定。

**能让朋友直接访问我的地址吗：** `127.0.0.1` 总是指访问者自己的电脑。朋友应下载本项目并连接自己的 Zotero。当前无登录和多用户隔离，不要直接将本电脑服务暴露到公网。

**相关文献查找失败：** 先看该页面底部各数据源的提示。401/403 通常需要在“检索设置”填写或更正对应学术服务的 Key；429 表示限流或额度不足。不要把模型 Key 填到检索服务中。单个来源失败时仍可使用另一来源的结果；没有准确定位起始论文时，核对候选或先在 Zotero 补充 DOI。“相似研究”降级为关键词检索时会标明，引用结果也不代表系统已读过全文。

**联合查找不贴合问题或筛选后为空：** 中文专业问题可补充英文检索词，并检查术语表和研究方向同义词。筛选仅作用于已取回的候选；缺少年份、综述或开放获取信息不会通过相应筛选。先重置筛选，再查看下方数据源状态；旧单篇缓存不含新字段时需主动更新。至少两篇在 Semantic Scholar 精确匹配才能使用它的联合推荐；该来源不可用时，仍可使用独立扩展与问题检索结果。修改表单不会改变当前结果，需点击查找；打开保存记录也不会自动联网。

**导出按钮不能点或下载数量与当前显示不同：** 需先完成并保存检索，再勾选至少一篇候选。检索进行中会暂时禁用导出。不感兴趣项需先恢复再勾选；筛选隐藏的已选论文仍会导出，工具栏会显示数量。切换页面后勾选会清空。若提示已选文献已不在保存结果中，重新打开结果并勾选即可，无需为了导出再联网刷新。RIS 可在 Zotero 的“文件 → 导入”中打开；导入为通用条目是本版为避免猜测文献类型的设计，需根据原文更正。

## 仍然没解决，如何反馈

打开 [故障反馈表](https://github.com/xej12/literature-reviewer/issues/new?template=bug_report.yml)，提供 Windows/Python 版本、代码版本或 ZIP 下载日期、复现步骤、完整错误文字、相关模型能力（无需 Key）。说明问题发生在启动、浏览、文字生成还是图片生成。

提交前遮住 API Key、个人路径、私人题录和受版权保护的全文。环境检查不会输出密钥；其他日志、截图仍需自己检查。不要上传整个 `data/` 或 Zotero 数据库。
